## Marketplace icon rejection and lossless fix

The first Marketplace attempt rejected `assets/pixel-minion-icon.png` for exceeding the 1024 KiB limit (1,166,630 bytes). No runtime issue was found.

The distribution PNG was re-encoded losslessly: PNG row filters selected by minimum sum of absolute signed residuals, zlib level 9 / memory level 9 / RLE strategy. The non-rendering `caBX` content-credentials chunk was omitted because it describes the original encoding and would no longer validate after recompression. Dimensions remain 1024×1024 RGB8; all 3,145,728 decoded pixel bytes are identical to the smoke-tested source. Decoded pixel SHA-256: `3ab36930ac64321ef0b3156a62145583c766d288c646a7df135c5ecd77f51bcb`.

The optimized PNG is 1,041,854 bytes. Only `extension/assets/pixel-minion-icon.png` differs between the smoke-tested and distributed VSIX entries. Runtime JavaScript, source maps, package metadata, prompts, README, changelog and every other entry are unchanged. Marketplace accepted the retry. GitHub's attached VSIX was then replaced with that same package.

The optimized source asset is committed with this completion record for future packaging. The public v1.4.0 tag is not moved: it identifies the smoke-tested release code with the original PNG encoding. The release distribution's sole source-asset difference is documented here; no version or runtime change was made.
